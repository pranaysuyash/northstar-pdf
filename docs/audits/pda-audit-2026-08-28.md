## 1. Method (how this audit was produced)

1. Selected PER-91002 as the operating persona because the request is explicitly a *first-principles* audit: decompose the product into underlying primitives before judging relevance, feasibility, or scope. PER-91013 is applied wherever a finding would close or delete a capability (no premature NO-GO; salvage useful children).
2. Read the repo-local `OPERATING_DOCTRINE.md` to anchor the three test dimensions the user asked about: **1st-principles** (root-primitive cause, not surface patch), **long-term** (reduces state complexity, avoids shadow pipelines, durable), **doctrine-aligned** (single canonical source, truth taxonomy, evidence tiers, additive value).
3. Launched 5 parallel read-only `explore` sub-agents, each scoped to one subsystem, returning file:line evidence and a truth status (Observed/Inferred). Sub-agents were bounded to "report findings, do not implement."
4. Reconciled IDs: the test-evidence sub-agent returned four `DOC-*` findings that collided with the documentation sub-agent's `DOC-*` series; renamed to `EV-01..EV-04` (evidence-claim findings).
5. Verified the project compiles (`swift build`) and captured metrics as independent Tier-1 evidence.
6. Synthesized the register, the implicit/explicit split, the three-way alignment scoring, best-in-class recommendations, and the implementation plan.

**Verdict notation used in the register:** each finding carries `1P/LT/DOC` —
- `Y` = a principled, long-term, doctrine-aligned corrective path is clear.
- `N` = a naive fix would itself violate doctrine (band-aid, second source of truth, or false-negative closure).
- `?` = needs a designed decision before implementation (usually a NO-GO/salvage call).

> **Meta-conclusion:** The *current* repo state is **not** fully doctrine-aligned. The defects themselves are predominantly doctrine violations — shadow pipelines, second sources of truth, unverified claims promoted to "validated/Implemented", synthetic data presented as observed, governance/detection that is UI-only. Every corrective task below is **aligned** when executed via primitive decomposition; the `N`/`?` marks flag the few places where a careless fix would *introduce* a new violation (those require the No-Go salvage discipline instead of blunt deletion).

**Conclusion:** 100% of corrective tasks are *achievable* in a first-principles, long-term, doctrine-aligned way. **0% of the *current* state is fully aligned** — the defects are themselves doctrine violations (second sources of truth, unverified claims, synthetic-as-observed, UI-only governance). The only places needing care are the 10 `N/?` items, where a naive fix (delete the feature/dashboard) would be a *false-negative closure* the No-Go persona forbids; those require **semantic salvage** (keep the useful child) before any removal.

**What is NOT yet aligned, and the principled shape of the fix:**
- The repo treats *aspirational capability* as *shipped capability* in at least 5 surfaces (sanitizer, redactor, signature verifier, PDF/UA, companion). Principled fix = a single `CapabilityClaim` registry where each claim carries an evidence tier (T0-T5/S0-S3) and a gate; UI/docs render only gated claims. This is the single highest-leverage structural change.
- The repo has *parallel models and contracts* (document model, companion contract ×3, session envelope ×2, capability enum ×3, version type ×4). Principled fix = collapse to one primitive each with a re-export shim during migration (canonical-path rule §5).
- The repo's *evidence gates don't gate* (parity prints, mutation is a no-op, performance baseline self-seeds). Principled fix = assertions that fail; downgrade the claim when the assertion can't yet pass, never mark PASS.

## 5. Recommendations to make it best-in-class (additions / improvements not yet present)

These go beyond fixing defects — they are the differentiators a best-in-class PDF tool needs and that the doctrine's "do smart things / be additive in value" demands:

1. **CapabilityClaim registry (new primitive).** One struct: `id, label, evidenceTier, gate, owner, lastVerified`. Every UI feature, doc claim, and release gate reads from it. Eliminates IMP-5/IMP-8 at the root. (1P/LT/DOC = Y/Y/Y)
2. **Single document-model primitive.** Demote `HybridPDFParser`/`PDFDocumentModel` to a thin importer; `PDFKitProvider.DocumentInspection` becomes the one model. Kills ENG-03/04/05/07. (Y/Y/Y)
3. **Real, consent-gated companion transport** (XPC or stdin/stdout bridge) with HMAC-verified handshake, or an explicit "companion: off by default, here's why" decision recorded as D-. Resolves ARC-05/06/07 without deleting the wanted capability. (salvage-aligned)
4. **Enforcement-bound governance.** Wire `runComplianceCheck` into open/import; make critical violations block with an operator override + audit entry. Resolves ARC-17/18. (salvage-aligned)
5. **Versioned, value-free persistence layer.** One store, schema-versioned migrations, default value-free, explicit consent for value-bearing fields. Resolves ARC-23/25/27/28. (Y/Y/Y)
6. **Evidence gates that fail.** Promote `independent-preservation-validator.mjs` (BM-03, genuine S3) to the parity reporter; add `assert.equal(totalUnexpected,0)`; fix the no-op mutation (TST-01) and tautology (TST-02); committed performance baselines. Resolves TST-09/EV-01/2/BM-01. (Y/Y/Y)
7. **Documentation canonical index + decision registry hygiene.** `docs/INDEX.md`, unique decision IDs, D-055 enforced, explorations quarantined, "proposed/strategy — not a commitment" banners, vendor `DOCUMENTATION_DOCTRINE.md`. Resolves DOC-01..30. (Y/Y/Y)
8. **Surface the WCAG suite + a11y as a first-class, always-on capability** (UI-01/02/03/19/21) — turn the dead core audit into the product's accessibility differentiator.
9. **Decompose the `AppModel` god-object** behind an `EditorViewState` view-model (UI-14/15/16/17/20) for testability and reviewability.
10. **Provenance integrity** in harness outputs (fix ENG-26/27 string-literal bugs) so every artifact is traceable — foundational for the evidence-tier system above.
