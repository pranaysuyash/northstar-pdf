## 1. Branch outputs (verbatim)

### Frame: Trust attacker (attacks negated into defenses)
1. **Hash-sealed genesis snapshot** — replay never resolves state from the live document tree; anchored to a hash-sealed genesis referenced inside the earliest receipt. *(Attack: swap the seed document, ride valid mutations into a forged end state.)*
2. **Non-transplantable receipts** — receipts commit to ledger-instance identity and chain position, never content hash alone. *(Attack: transplant real receipts onto a fabricated ledger.)*
3. **Lineage-import quarantine** — a genesis matching an existing sealed document must import that receipt chain as lineage or be quarantined as unverifiable. *(Attack: launder a mutated document via a parallel tool, re-import as "new.")*
4. **Net-zero smuggling rejection** — the reconciler rejects offsetting mutation pairs bracketing unrelated mutations. *(Attack: balanced-looking pairs smuggle unsealed intermediate state past the trial balance.)*
5. **Capability-bound attribution** — stem attribution bound to stem-held capability and sealed logical sequence numbers, never wall-clock time or session claims. *(Attack: assert changes under a stem you don't control; resequence authorship via clock manipulation.)*
6. **Causal lineage persistence** — revert/reapply mutations inherit the causal provenance of restored content; AI-authored content keeps its AI lineage through any number of human hands. *(Attack: launder AI authorship via revert-and-reapply re-badging.)*

### Frame: Second-lane designer
1. **Edit-pattern induction** — after repeated manual corrections, the model proposes a reusable rule; deterministic replay of the rule must reproduce those exact past mutations before the user ratifies it.
2. **Version-contradiction triage** — the model classifies hunks between versions as semantic conflicts vs harmless rewording, proposing inert ledger tags.
3. **Obligation extraction** — structured commitments (party, deadline, amount) proposed from prose, each anchored to an exact verbatim span the validator re-matches.
4. **Import ontology mapping** — model proposes field mappings for unmatched incoming documents, gated by deterministic type/cardinality checks.
5. **Skeptical-auditor pass** — the model drafts what a hostile reviewer would challenge, as span-anchored challenge proposals, inert until filed.
6. **Mutation materiality tagging** — the model classifies each ledger entry as substantive or cosmetic; the validator confirms the tag's spans agree with the recorded diff.

### Frame: Cartographer
1. **Beck-style transit diagram** — lines are people, stations are ledger events, merges/reverts are interchange symbols.
2. **Terrae incognitae layer** — regions with no receipts (pre-ledger imports, bulk fills, paste-ins) rendered as honest blank space: "here be dragons."
3. **Projection switcher** — each mode declares its distortion: equal-area (every edit weighs the same), Mercator-of-recency, attestation-conic.
4. **Live legend** — every map symbol IS its receipt; tap the disputed-border hatch and the exact ledger row opens beneath the key.
5. **Themed atlas plates** — contributor plate, dispute plate, attestation plate, sharing one graticule so a single grid reference resolves across all.
6. **Provenance hydrology** — every clause fed by rivers draining to contributor springs; authorship reads as watershed.

### Frame: Aviation CRM
1. **Sterile cockpit for the approver** — during high-stakes mutation windows the surface locks the canvas to the affected region and disables competing affordances.
2. **Approver fatigue management** — approval cadence tracked; dwell time below plausible reading speed forces a cooldown or raises interaction cost.
3. **Non-punitive near-miss register** — one-click "almost approved that" self-reports feeding a personal ASRS-style log surfaced at future briefings.
4. **Readback/hearback on intent** — the agent restates what it heard; approval attaches to the readback, not the raw instruction.
5. **Brief-and-fly-the-brief** — the agent opens with a briefing card (what it will do, where it expects to need you, abort criteria); only deviations interrupt; on-brief progress streams.
6. **Puzzled-look rule** — hesitation (stalled cursor, hover-without-click) auto-holds the operation; the agent must surface its basis, never reading silence as consent.

### Frame: Watchmaker
1. **Deadbeat rendering** — the interface may only advance on committed ledger ticks; no speculative, optimistic, or in-between states, ever.
2. **Tourbillon regulation** — deterministic heuristics rotated through counterfactual "positions"; only position-averaged results commit.
3. **Perpetual ordering** — wall-clock time is a display complication only; the ledger's causal spine is a monotonic tick.
4. **Jewels** — hardened invariants placed at the highest-friction mutation seams, with the count displayed ("Northstar: 23 jewels").
5. **Spare-parts covenant** — every ledger op carries a stable part number in a published catalog; a third party can build a working servicer decades later.
6. **Crown-out hack** — one gesture freezes the entire workspace at a named tick for exact-second comparisons and captures.

## 3. Deepened branches (focus-agent output; agent verified source schemas)

### R6-14 Terrae incognitae layer (cluster M) ★ — top of round (9.60)
**Sketch:** A pure derivation from data the app already has: for each rendered region, intersect the region map against the union of ops' touched-resource sets (operation-region data + evidence graph), classify uncovered regions by import class, and render them with a neutral hatch and a confessional label ("no ledger testimony — pre-ledger source") — never red, because the doctrine is honesty, not alarm. Deterministic over (ledger, import class, touched-resource geometry); recomputes on every append; history scrubbing falls out free (pin the ledger anywhere and the map recomputes). Degrades by granularity: page-level attribution testifies at page level and says so, never fabricating region-level knowledge.
**Load-bearing risk:** the region-to-resource attribution mapping — if ops commonly lack region geometry, the computation fails in two dishonest directions: false coverage (marking untestified regions as covered — direct D-067 violation, the worst outcome) or blanket hatching (map useless, users trained to ignore it).
**First concrete step:** a read-only coverage audit — diagnostic pass over real documents joining each op's touched-resource set to region geometry, reporting the fraction of ops carrying region-level sets and which import classes own the rest. Zero UI; the output decides whether the layer ships at region, page, or document granularity.
**Children:** coverage provenance by import class (diagnostic, not accusatory) · show-the-derivation inspector (audit the audit) · pre-ledger attestation sweep (owner confirms blank regions against source; advisory-class entries convert blank territory progressively) · incognita regression detector (fires when an op should cover a region that still computes unattributed — a development-time gate on the attribution system itself, likely the highest near-term value) · granularity ladder in the vocabulary (absorbs the load-bearing risk into the design).

### R6-06 Causal lineage persistence (cluster K) ★ — 9.20
**Sketch:** Ledger entries (`EditOperation` in `DocumentModel.swift`) already carry `id`, `parentOperationID`, `sourceDigest`, `previousValue` — but nothing records what content an operation causally *restores*, so revert+reapply re-badges agent-authored bytes as a fresh owner delta. The fix adds two backward-compatible optional fields: `resultDigest` and `restores: [UUID]`, emitted by the executor for every resurrection-class path (revert, reapply, undo, redo, snapshot-restore, plan re-proposal). Attribution becomes a pure deterministic function of the ledger: replay builds a provenance DAG where an owner-class entry restoring agent content inherits "performed by owner, originated by agent plan P" — lineage follows content spans, not documents (a human who rewords AI text authors the delta; unchanged restored spans keep agent lineage — a causal record, not a taint stamp). Export→import round trips degrade honestly: exports embed a lineage sidecar; re-import without one lands in the existing `import` stem marked "provenance unverifiable beyond this point."
**Load-bearing risk:** the inheritance rule is enforced at write time and the ledger has no cryptographic trust root — receipts are tamper-*evident*, not tamper-proof. The defense covers laundering through Northstar-mediated operations only; D-067 requires scoping the promise exactly that way. Over-claiming "unforgeable AI provenance" would be the identity-defining product breaking its own honesty contract.
**First concrete step:** failing fixture test first — agent mutation reverted then re-applied by owner; extend `EditOperation` with optional `resultDigest`/`restores` (legacy entries decode as contributor-class attribution only); implement `computeLineage(ledger) -> ProvenanceDAG`; assert the re-applied content reports agent-originated.
**Children:** span-level lineage via per-op diffs · resurrection-op taxonomy completeness audit (the laundering attack migrates to whichever resurrection path is uninstrumented — coverage of the taxonomy is the invariant) · replay-convergence invariant (every state re-derivation recomputes lineage and must converge; mismatch = integrity failure, ledger unchanged on failure — a D-078 extension) · lineage sidecar with named degradation · performed-by vs originated-by split in the attribution UI.

### R6-25 Deadbeat rendering (cluster O) ★ — 8.95
**Sketch:** The document UI becomes a pure projection of one published value — a LedgerHead {seq, stateDigest, receiptVerified} advancing only when a new entry's receipt verifies. A "tick" is precisely that verified commit; frames may coalesce fast ticks but may never appear without one. All document views render as f(head) from a single projection store with no local @State shadows of document content, making optimistic updates structurally impossible rather than discouraged. Zoom/scroll/selection stay exempt as D-068 view-session state; typing resolves through a draft buffer that commits as one ledger entry on a completion gesture, rendered in a visually segregated "draft" treatment until its tick lands — committed pixels are provably ledgered, draft pixels are labeled as non-ledger and excluded from digest, export, and agent binding. Enforcement is mechanical: a CI/frame test asserts rendered content hashes to the current head digest.
**Load-bearing risk:** perceived-latency collapse — commit latency becomes input latency with no optimistic escape hatch by design. Survives only if p99 gesture-to-tick latency holds a strict budget and the typing draft-buffer carve-out covers the highest-cadence case; secondarily the ledger/view-session boundary will erode under product pressure unless enforced by architecture and tests, not convention.
**First concrete step:** define the Tick type and build a head-only LedgerProjectionStore; migrate the existing receipts timeline (read-only, already ledger-shaped) to render exclusively from it; CI test asserting the rendered timeline equals the projection of the current head — prove frame==head on the cheapest surface before any interactive surface migrates.
**Children:** formalize the intent/document ledger boundary (drafts excluded from digest/export/agent binding) · commit-latency budget + tick-rate telemetry (p99 gate in CI) · frame-digest invariant as debug HUD + lint against @State shadows of document content · design the visible beat (tick-motion language, reduce-motion gated per MAD-I8; head/seal badge visibly increments; coalescing rule: many ticks may collapse into one frame, never the reverse) · migration ladder as claim-tiered rollout (tier 1 read-only ledger displays → tier 2 annotation mutations → tier 3 text drafting).

## 5. Provocation

Six rounds keep converging on one sentence: **the interface is under oath.** Deadbeat rendering = pixels cannot lie about state; lineage = authorship cannot be laundered; terrae incognitae = the map confesses what it doesn't know; trial balance = the ledger proves it reproduces reality. The wildcard that opens the next round: **when is provability the wrong tool?** Creative flow, speed, privacy of thought, the messiness of drafting — a registry clerk is sworn to testimony, but people also think out loud. Is there a mode where the ledger deliberately *doesn't look* — and what does that mode owe the honesty doctrine?
