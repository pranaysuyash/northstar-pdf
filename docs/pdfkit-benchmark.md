## Purpose

This is the first native provider evaluation lane. It tests whether PDFKit can
support a safe, bounded-filling foundation on the attached static Form 6 fixture.
It does not test static-region detection accuracy, arbitrary text reflow, OCR, PDF
signing, redaction, or production readiness.

## Claims Under Test

| ID | Claim | Failure consequence | Evidence target |
|---|---|---|---|
| PK-01 | PDFKit can open and inspect the fixture without treating it as a native form | Incorrect product mode or false native-field confidence | Tier 2, S1; S3 later with a deliberate fixture mutation |
| PK-02 | PDFKit can render both pages and expose stable page/text geometry | Incorrect review coordinates or visual output | Tier 2, S1 |
| PK-03 | A no-op PDFKit save can be reopened with equivalent page/text/widget state | Silent fidelity regression or unusable export | Tier 2, S1; independent viewer later |
| PK-04 | A bounded annotation can be added to a new copy and reopened with its expected bounds | Misplaced or unrecoverable user edit | Tier 2, S1 |
| PK-05 | The source bytes remain unchanged after inspection and export | Data loss or provenance break | Tier 2, S1 |

## Fixed Inputs

- The source PDF bytes and SHA-256 digest.
- The expected page count, dimensions, rotation, text-nonempty state, and zero
  native-widget inventory recorded in [`form6-benchmark.md`](form6-benchmark.md).
- The output directory and artifact names emitted by the harness.
- Apple SDK/provider identity and the exact compile target.

## Harness Operations

1. Load the fixture with `PDFDocument`.
2. Record page count, PDF version, encryption/lock state, page boxes, rotation,
   text character counts, and annotation/widget counts.
3. Render each original page to PNG using `PDFPage.drawWithBox:toContext:`.
4. Write a no-op output copy and reopen it.
5. Render each reopened no-op page and compare its PNG bytes to the original render.
6. Add one bounded `FreeText` annotation to a new in-memory document copy, write a
   separate overlay output, reopen it, and verify annotation type, count, bounds,
   and unchanged extracted page text.
7. Emit a JSON result and preserve artifacts for review.

## Independent Oracles

- The fixture digest is independently checked with `shasum`, not generated by the
  harness itself.
- Page count, dimensions, form inventory, and text presence are grounded in the
  previously reviewed Poppler inspection.
- PNG equality compares independently written render artifacts from the original
  and no-op-reopened documents using the same PDFKit provider. Cross-provider PNG
  comparisons require a pixel tolerance because renderer rasterization can differ.
- Annotation round-trip checks the PDFKit object model after reopening; it is not a
  claim that every external PDF viewer renders the annotation identically.
- A separate extractor may include the expected annotation contents in extracted
  output. The overlay text oracle therefore applies to the PDFKit provider's page
  text, while cross-provider extraction must account for the expected new annotation
  content.

## Hard Failure Gates

- Source SHA-256 changes.
- Fixture cannot be reopened, or output cannot be reopened.
- No-op render differs byte-for-byte from the original render.
- Native widget inventory is nonzero for Form 6.
- Overlay output changes extracted page text unexpectedly.
- Any failure is reported as success.

## Known Limits

- `qpdf` is not installed locally, so structural JSON validation is not part of the
  first run.
- No independent viewer check is available in this headless harness.
- PNG equality is a strong render check for this environment, not a universal PDF
  semantic-preservation proof.
- Form 6 does not exercise native widgets, rotated pages, signatures, encryption,
  malformed input, scans, or large documents.
- No static candidate detector is implemented in this lane.

## Runtime Result

### Run 2026-08-23: Form 6

- **Command:** `PDF_EDITOR_BENCHMARK_OUTPUT_DIR=benchmark/results/2026-08-23-pdfkit-form6 bash benchmark/test_pdfkit_benchmark.sh`
- **Environment:** Xcode 26.3, Swift 6.2.4, macOS SDK 26.2, arm64 target
  `arm64-apple-macosx15.0`.
- **Result:** Exit status `0`; machine result is preserved at
  [`../benchmark/results/2026-08-23-pdfkit-form6/result.json`](../benchmark/results/2026-08-23-pdfkit-form6/result.json).
- **Observed:** Two pages, 612 x 841.68 points, zero native widgets, non-empty
  extracted text, two rendered pages, successful no-op reopen, equal PDFKit-local
  original/no-op PNGs, one reopened bounded FreeText annotation, unchanged
  provider-extracted text, and unchanged source digest.
- **Evidence:** Tier 2 targeted runtime check; S1 pass. This is not S2 because no
  pre-existing defect was being closed, and not S3 because no deliberate mutation
  was run.
- **Independent Poppler check:** Original/no-op extracted text matched. The overlay
  extraction included the expected `PDFKit benchmark` annotation contents. At 144
  DPI, Poppler raster comparison reported page 1 absolute error `0` and page 2
  absolute error `85` (`4.12378e-05` normalized metric). This is a small but real
  cross-renderer variance and remains a fidelity risk, not a hidden pass.
- **Structural check:** Poppler reports both no-op and overlay outputs as two-page,
  612 x 841.68 point, unencrypted, JavaScript-free PDFs. `qpdf` remains unavailable.
- **Residual risk:** The lane does not prove arbitrary editing, static detection,
  signatures, redaction, malformed-input handling, rotated pages, native widget
  mutation, independent-viewer equivalence, or production readiness.
