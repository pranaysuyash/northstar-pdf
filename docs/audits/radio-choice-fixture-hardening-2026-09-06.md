## Measured engine semantics (not assumed)

1. **pdf-lib maps `/Ch` to two classes.** `PDFDropdown` when the combo bit (18) is set, `PDFOptionList` (listbox) otherwise. The lane previously typed only `PDFDropdown` as `choice`, so listbox-type choices were invisible to the pdf-lib provider — a real coverage gap found by the new fixtures and fixed in `lane.mjs` (both ctors → `choice`; write path falls back `getDropdown` → `getOptionList`).
2. **Pair-form /Opt: viewer-facing strings.** pdf-lib's `getOptions()`/`select()` and PDFKit's `widgetStringValue` both operate on the **display** string for `[export, display]` pairs (pdf-lib's `select()` rejects export values and writes the display string as `/V`). The structural model (our `walkAcroForm`) decodes the **export** element, which is what `/V` comparisons require. Both behaviors are now measured and documented in the test suite rather than forced to agree.
3. **Two writer bugs found and fixed** (`PDFIncrementalFormWriter`):
   - `incrementalFieldUpdate` appended one copy per edit; two edits to the same object (choice `/V` + `/AP` appearance) produced two xref entries for one object number and the later copy silently dropped the earlier pair. Edits are now coalesced per object (last pair wins on duplicate keys).
   - `insertIntoDict` inserted missing keys at a stale index captured before replacement-length changes — splicing `/AP <<…>>` inside a `/V (ground)` string on merged field+widget objects. Missing keys now append at the true end of the dict.
   - `topLevelArrayElements` (new `/Opt` splitter) tracked string-vs-bracket depth in one counter, merging whole arrays into one element. Rewritten with independent `bracketDepth` and `inString` states.
